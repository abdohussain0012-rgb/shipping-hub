# Shipping Hub

نظام متابعة الشحنات للتيم: Dashboard للملخص اليومي، ومتابعة كل الشحنات، وتقارير بالتسليم والتكلفة والأداء حسب الشركة والفرع والمندوب.

**التقنيات:** Next.js (App Router) · TypeScript · Tailwind CSS · Supabase (PostgreSQL + Auth + Row Level Security) · الاستضافة على Vercel.

---

## 1. إعداد Supabase (مرة واحدة)

1. ادخل على [supabase.com](https://supabase.com) واعمل **New project**. اختار منطقة قريبة (Frankfurt أو Europe مثلاً).
2. من **SQL Editor ← New query**، الصق محتوى الملف `supabase/schema.sql` كله واضغط **Run**.
   الملف بيعمل الجداول والصلاحيات (RLS) وسجل التعديلات والتقارير. تقدر تشغله تاني من غير مشكلة.
3. **لو المشروع موجود من قبل** (قبل تحديث الدخول والدعوات): شغّل كمان `supabase/migrations/002_auth_hardening.sql` **مرة واحدة**.
   ده بيقفل قراءة البيانات على أعضاء الفريق بس، ومش بيغيّر أو بيمسح أي بيانات.
4. من **Project Settings ← API** انسخ:
   - `Project URL`
   - `anon public` key (أو `Publishable key` لو ظاهر عندك)

   **ما تستخدمش** مفتاح `service_role` في الواجهة أبداً، ولا تحطه في أي ملف يبدأ بـ `NEXT_PUBLIC_`.
5. **أول أدمن:** من **Authentication ← Users ← Invite user** اكتب إيميلك، وافتح الرسالة اللي هتوصلك واختار كلمة المرور.
   بعدين من **SQL Editor** شغّل:

   ```sql
   update public.profiles
   set role = 'admin'
   where id = (select id from auth.users where email = 'your-email@example.com');
   ```

6. (مُستحسن) فعّل **MFA** لحساب الأدمن من إعدادات حسابك في Supabase.

## 2. إعدادات الدخول والدعوات (مهم)

دي إعدادات من لوحة Supabase مش من الكود. اعملها مرة واحدة، وقبل ما تبعت أي دعوة للتيم.

### 2.1 منع التسجيل المفتوح

من **Authentication ← Sign In / Providers** (أو **Providers ← Email**)، **امسح علامة** `Allow new users to sign up`.
ده بيمنع أي حد يعمل حساب بنفسه. الدعوات اللي بيبعتها الأدمن من **Invite user** هتفضل شغالة.

### 2.2 روابط الموقع

من **Authentication ← URL Configuration**:

- **Site URL:** `http://localhost:3000` وانت بتجرب على جهازك. ولما تنشر على Vercel غيّره لرابط الموقع (مثلاً `https://shipping-hub.vercel.app`).
  **لازم يكون الرابط ده صح قبل ما تبعت أي دعوة**، لأن الإيميلات بتفتح على الـ Site URL.
- **Redirect URLs:** ضيف `http://localhost:3000/**` ورابط Vercel بتاعك مع `/**` في الآخر.

### 2.3 قوالب الإيميل

من **Authentication ← Email Templates**:

- **Invite user:** في نص الإيميل، بدّل `{{ .ConfirmationURL }}` بالرابط ده:

  ```
  {{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=invite&next=/auth/update-password
  ```

- **Reset password:** نفس الخطوة، بس الرابط يكون بـ `type=recovery`:

  ```
  {{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/auth/update-password
  ```

احفظ القالب بعد كل تعديل. الزرار اللي في الإيميل هيفتح صفحة تعيين كلمة المرور داخل الموقع.

## 3. التشغيل محلياً

```bash
npm install
cp .env.example .env.local      # وحط القيم من Supabase
npm run dev
```

- افتح `http://localhost:3000` وسجّل دخول بحساب الأدمن.
- **بعد أي تعديل في `.env.local` لازم توقف `npm run dev` (Ctrl+C) وتشغّله تاني.** Next.js بيقرأ الملف مرة واحدة عند التشغيل.

## 4. النشر على Vercel

1. ارفع المشروع على GitHub (repository خاص).
2. من [vercel.com](https://vercel.com) اعمل **Add New ← Project** واختار الـ repository.
3. في **Environment Variables** ضيف:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. اضغط **Deploy**. كل push على `main` بيتنشر لوحده.
5. ارجع لـ Supabase وحط رابط Vercel في **Site URL** (القسم 2.2).

## 5. ضيف أعضاء التيم

الأدمن بس هو اللي بيضيف أعضاء. مفيش تسجيل مفتوح.

1. من Supabase ← **Authentication ← Users ← Invite user** اكتب إيميل الشخص.
2. الشخص بيفتح الإيميل ويضغط على الزرار، ويختار كلمة مرور (8 حروف على الأقل)، وبعدين بيدخل على النظام.
3. من صفحة **المستخدمون والصلاحيات** غيّر صلاحيته:
   - **أدمن:** كل حاجة، بما فيها حذف الشحنات وتغيير الصلاحيات.
   - **مدير:** الاستيراد، التقارير، إدارة الفروع والمندوبين، وتحديث الشحنات.
   - **موظف:** متابعة الشحنات وتحديث حالتها وإضافة ملاحظات.

**لو الدعوة ماوصلتش أو انتهت:** من Supabase ← Users ← اختار الشخص ← **Send password recovery**. ده بيبعت إيميل جديد يفتح صفحة تعيين كلمة المرور.

**لو الشخص نسي كلمة المرور:** يضغط **نسيت كلمة المرور؟** في صفحة الدخول، ويوصله رابط على الإيميل.

## 6. استيراد ملفات الشركات

الصفحة: **استيراد ملفات الشركات**. اختار الشركة وارفع ملف CSV.

**الأعمدة:**

| العمود | المعنى | النوع |
|---|---|---|
| `awb` | رقم الشحنة من الشركة | مطلوب |
| `status` | الحالة كما تظهر في ملف الشركة | مطلوب |
| `reference` | رقم الأوردر أو المرجع | اختياري |
| `branch` | اسم الفرع (بيتضاف تلقائياً لو جديد) | اختياري |
| `agent` | اسم المندوب (بيتضاف تلقائياً لو جديد) | اختياري |
| `order_value` | قيمة الأوردر | اختياري |
| `shipping_cost` | تكلفة الشحن | اختياري |
| `cod_amount` | مبلغ التحصيل عند الاستلام | اختياري |
| `shipped_at` | تاريخ الشحن | اختياري |
| `delivered_at` | تاريخ التسليم | اختياري |

- أسماء الأعمدة ممكن تكون عربي أو إنجليزي، ومش مهم الترتيب.
- التواريخ: `YYYY-MM-DD` أو `DD/MM/YYYY`.
- الشحنة بتتحدث بالـ AWB، فإعادة رفع نفس الملف مش هتكرر الشحنات.
- الخانة الفاضية **ما بتمسحش** القيمة القديمة.
- **الحالات المش متعرفة:** لو الشركة كتبت حالة ما اتضافتش في صفحة **توحيد الحالات**، الشحنات دي بتتخطى وبتظهر في نتيجة الاستيراد. ضيف الحالة في توحيد الحالات وارفع الملف تاني.

**الحالات الموحدة:** بانتظار الاستلام، في الطريق، خرجت للتسليم، تم التسليم، فشل التسليم، مرتجع، ملغي.

## 7. الأمان وسجل التعديلات

- **RLS مفعّل على كل الجداول:** أي سحب أو تعديل بيتم بصلاحية المستخدم اللي دخل، وده بيتطبق حتى لو حد وصل للـ API مباشرة.
- **القراءة للفريق بس:** الحساب اللي مالهوش صف في جدول `profiles` (يعني مش من الفريق) مش بيقدر يقرأ أي بيانات.
- **مفيش تسجيل مفتوح:** الحسابات بتتضاف بدعوة من الأدمن بس (القسم 2.1).
- **سجل التعديلات** (`shipment_events`) بيتسجل تلقائياً من قاعدة البيانات: كل إنشاء أو تغيير حالة، ومعاه اسم المستخدم ووقته. السجل ده **للقراءة والإضافة بس**، مش بيتعدل ولا بيتمسح.
- الصلاحيات بتتحدد من جدول `profiles`، وتغييرها للأدمن بس.
- **مفتاح `service_role` ما بيدخلش الكود أبداً.** الموقع بيستخدم المفتاح العام (`anon` / `publishable`) بس.

## 8. مشاكل شائعة

| الأعراض | السبب | الحل |
|---|---|---|
| "الإيميل أو كلمة المرور غلط" لحساب اتعمل بدعوة | الشخص لسه ما حددش كلمة مرور | اضغط **نسيت كلمة المرور؟** أو استخدم **Send password recovery** (القسم 5) |
| رابط الدعوة بيفتح صفحة الدخول بدل صفحة تعيين كلمة مرور | قالب الإيميل قديم، أو الـ Site URL غلط | راجع القسم 2.2 و 2.3 |
| "إعدادات الاتصال بـ Supabase ناقصة" | `.env.local` ناقص أو مش متقرأ | تأكد من الملف، وأعد تشغيل `npm run dev` |
| "الرابط ده منتهي" | الرابط اتستخدم قبل كده أو انتهت صلاحيته | اطلب رابط جديد |
| "حسابك مش مفعّل" | الحساب مش له صلاحية في النظام | الأدمن يحدد صلاحيته من **المستخدمون والصلاحيات** |

## 9. البنية

```
supabase/schema.sql                  الجداول، RLS، الـ triggers، دوال التقارير
supabase/migrations/002_*.sql        تحديث صلاحيات القراءة (للمشاريع القديمة)
src/middleware.ts                    حماية كل الصفحات وتجديد الجلسة
src/lib/                             auth، auth-errors، format، status، csv، import-schema
src/lib/supabase/                    الاتصال بـ Supabase (env، server، middleware)
src/app/login                        تسجيل الدخول
src/app/forgot-password              طلب رابط نسيت كلمة المرور
src/app/auth/confirm                 يستقبل روابط الدعوة وإعادة التعيين من الإيميل
src/app/auth/update-password         صفحة تعيين كلمة المرور
src/app/(app)/dashboard              الملخص اليومي
src/app/(app)/shipments              متابعة الشحنات وتفاصيل كل شحنة
src/app/(app)/reports                التقارير (شركة / فرع / مندوب) مع تصدير CSV
src/app/(app)/import                 استيراد ملفات الشركات
src/app/(app)/settings/*             توحيد الحالات، المستخدمون والصلاحيات
src/app/api/reports/export           تصدير التقرير CSV
```

## 10. الخطوة الجاية (مقترحة)

- ربط الـ API بكل شركة عشان الحالات تتحدث لوحدها بدل الرفع اليدوي.
- تنبيه يومي بالشحنات المتأخرة على الإيميل أو واتساب.
- صلاحيات على مستوى الفرع (المندوب يشوف فرعه بس) لو احتجتها.
- إضافة عضو من داخل الموقع بدل لوحة Supabase (يحتاج مفتاح `service_role` على السيرفر بس).
